# OpenGL rasterizer plan

## Current state

The MVP requires an OpenGL 4.3 context and accelerates draws that use RGBA8 or RGB8 targets with tile-aligned dimensions and no procedural texture. The fragment shader is one uber-shader: the texture environment's six combiner stages run from uniform arrays (sources, operands, operations, constants, scales, the buffer update bits and its initial color), so no draw ever waits on a shader compile and no shader cache is needed. The texture units sample decoded RGBA textures, every common PICA format included (RGBA8 through A4 and the ETC1 pair), by reusing Zakuro's CPU texture decoder — the GL side never sees a compressed format. Wrapping, filtering and level-of-detail selection follow the software rasterizer's own math in the shader (texel-index wrap modes including the border color, nearest and bilinear, the analytic level from the rate the coordinates change across the screen, the bias and bounds, and the two-level blend), so samples match texel for texel.

PICA fragment lighting runs in the same uber-shader, from the words `Lighting::pack` already lays out for the hardware renderer: the per-light colors, positions, directions, spot vectors and distance biases ride a few `uvec4`/`vec4` uniform arrays that go up only when a draw decodes different lighting, and the twenty-four lookup tables (specular distributions, fresnel, the reflections, a spotlight and a distance table per light) share one RG32F texture whose rows upload a table at a time, only when an entry changed since the last draw — five texture units in all, three for the guest textures and one for the lighting and fog tables. The shader reproduces `Lighting::shade` exactly: per-fragment quaternion and view interpolation with the per-triangle hemisphere flip, the bump normal and tangent reads off the sampled textures, the shadow texture over the primary and secondary sums, the spotlight and distance attenuations, the fresnel into the alpha the combiners read, the clamped highlights and the geometric factors, all quantized to the 255ths the software hands the combiners. The fog mixes in the same shader after the alpha test judges the fragment, by its depth through the fog table's row of the shared LUT texture and the fog color register, gas mode staying on the CPU like the software leaves it. Lighting feeds the combiners as the primary and secondary fragment colors, so a combiner that reads neither keeps the lighting off entirely.

An RGB8 target keeps an RGBA8 GL texture and framebuffer: guest tiles decode through Zakuro's own `ColorFormat` (3 bytes a texel, Morton tiled) into RGBA rows for the upload, blending runs in GL's fixed function with the copy's alpha channel held at the 255 the format decodes (no draw may write it, so a destination-alpha factor sees the 1.0 the software sees), and readback packs the drawn pixels back into the guest's own 3-byte tiles. Everything else about the targets — the keyed cache, the dirty tracking, the overlap resolution — is format-blind.

The output merger's alpha test, blending and partial color masks run in GL's fixed function, for every equation and factor pairing GL takes (a saturate factor on the destination side, which GL refuses, stays on the CPU). It supports depth/stencil tests and writes for D16, D24, and D24S8 attachments. Zakuro still runs the vertex shader, clipping, and culling on the CPU; OpenGL rasterizes the resulting triangles, interpolating the vertex color, texture coordinates, surface quaternion and view vector.

Decoded textures stay resident in an LRU cache of GL textures keyed on the CPU decoder's own texel allocation: a texture the CPU decoded again (memory changed under it) is a new allocation and uploads again, and one the CPU kept rides the GL texture it already has, so every invalidation path the CPU texture cache has (draws into overlapping targets, fills, display transfers, CPU writes between command lists) applies to the GL copy with no hooks of its own. Render-to-texture falls out of the same ordering: a texture overlapping a dirty GL surface resolves that surface into guest memory before the decode samples it. The keyed color/depth targets of the MVP stay, with their own 128 MiB LRU budget; the texture cache runs under 64 MiB.

The differential test suite in `crates/zakuro-gpu/src/raster/opengl_differential.rs` runs the CPU and OpenGL backends on identical guest memory and compares the bytes each leaves behind, with explicit tolerances where float math and driver rounding legitimately differ (see TODO.md for coverage and findings). It covers the output merger — the alpha test, blending, partial color masks and their combination over depth and stencil writes — and cache eviction, which it exercises by turning the budgets down. The texture work is covered the same way: every texture format, all sixteen wrap-mode pairs and the border color, nearest and bilinear filtering, level-of-detail selection and its bias and two-level blend, every combiner operation across stages with the buffer, constants and scales, multi-unit draws with the coordinate set and projection, texture-cache reuse, invalidation on rewritten bytes, and eviction, render-to-texture sampling, and fallback equivalence for procedural textures. Fragment lighting draws match a rounding step a channel across the whole state: the diffuse and specular sums, spotlight, distance, fresnel, ambient, shadow, bump and the tangent tables of the last configuration, plus the table rewrite and the lighting switch that reach the GL between draws; the fog matches behind an alpha test; and RGB8 targets match byte for byte, blends and masks included. It needs an OpenGL 4.3 context: on headless Linux it builds one through GLX on the software rasterizer (`xvfb-run -a cargo test -p zakuro-gpu --features opengl`), and where no context can be made the GL-dependent tests report why and pass while the conversion unit tests run everywhere.

## Implementation sequence

1. **Done.** Focused comparison tests for OpenGL coverage, interpolation, culling, scissoring, tiled-buffer conversion, depth/stencil state, depth mapping, lazy FBO caching and synchronization, and CPU-fallback equivalence run against the CPU path. Coverage and deferred cases are listed in TODO.md.
2. **Done.** Texture formats and sampling: the CPU decoder's texels upload into cached GL textures, and the shader reproduces the software rasterizer's wrap modes, filters and level-of-detail selection.
3. **Done.** The output merger (alpha test, blending, color masks) is accelerated and pinned by the differential suite, and the texture environment runs in the uniform-driven uber-shader — all six stages, every operation, the combiner buffer, constants and scales. The fallback keeps what GL cannot take (logic ops, a destination-side saturate factor) and what the shader does not run yet (procedural textures).
4. Move PICA vertex shader execution to OpenGL and handle geometry-shader draws through CPU preparation.
5. **Done for lighting, the fog blend and RGB8.** Fragment lighting runs in the uber-shader from `Lighting::pack`'s own words, its tables in one shared LUT texture; the fog mixes by depth through its table's row there; an RGB8 target keeps an RGBA8 copy and packs the guest's 3-byte tiles both ways. Still open from this step: procedural textures and the 16-bit framebuffer formats (RGB565, RGB5A1, RGBA4), which stay on the CPU; the lighting's fog test (gas mode) is unimplemented everywhere, matching the software path.
6. **Done as part of the MVP.** Keyed OpenGL color/depth targets already stay resident across draws, dirty GPU attachments are tracked, and synchronization resolves overlapping fallback draws, CPU reads/writes (the sync hooks), fills, and display transfers. The differential suite covers each of those paths; finer dirty-rectangle tracking to cut the writeback cost stays open in TODO.md.
7. Add resolution scaling, pipeline/resource caching, texture-pack support on the GPU path, and assess direct presentation and frame interpolation separately.
8. Validate the complete path on OpenGL 4.3 hardware across supported operating systems; retain software fallback for unsupported drivers and unimplemented states.
