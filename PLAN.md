# OpenGL rasterizer plan

## Current state

The MVP requires an OpenGL 4.3 context and accelerates draws that use RGBA8 targets with tile-aligned dimensions and no lighting, fog, procedural textures, or logic operation. The fragment shader is one uber-shader: the texture environment's six combiner stages run from uniform arrays (sources, operands, operations, constants, scales, the buffer update bits and its initial color), so no draw ever waits on a shader compile and no shader cache is needed. The texture units sample decoded RGBA textures, every common PICA format included (RGBA8 through A4 and the ETC1 pair), by reusing Zakuro's CPU texture decoder — the GL side never sees a compressed format. Wrapping, filtering and level-of-detail selection follow the software rasterizer's own math in the shader (texel-index wrap modes including the border color, nearest and bilinear, the analytic level from the rate the coordinates change across the screen, the bias and bounds, and the two-level blend), so samples match texel for texel. Draw state the uber-shader cannot run — fragment lighting colors, fog, procedural textures — still sends the draw to the CPU rasterizer.

The output merger's alpha test, blending and partial color masks run in GL's fixed function, for every equation and factor pairing GL takes (a saturate factor on the destination side, which GL refuses, stays on the CPU). It supports depth/stencil tests and writes for D16, D24, and D24S8 attachments. Zakuro still runs the vertex shader, clipping, and culling on the CPU; OpenGL rasterizes the resulting triangles, interpolating the vertex color and texture coordinates.

Decoded textures stay resident in an LRU cache of GL textures keyed on the CPU decoder's own texel allocation: a texture the CPU decoded again (memory changed under it) is a new allocation and uploads again, and one the CPU kept rides the GL texture it already has, so every invalidation path the CPU texture cache has (draws into overlapping targets, fills, display transfers, CPU writes between command lists) applies to the GL copy with no hooks of its own. Render-to-texture falls out of the same ordering: a texture overlapping a dirty GL surface resolves that surface into guest memory before the decode samples it. The keyed color/depth targets of the MVP stay, with their own 128 MiB LRU budget; the texture cache runs under 64 MiB.

The differential test suite in `crates/zakuro-gpu/src/raster/opengl_differential.rs` runs the CPU and OpenGL backends on identical guest memory and compares the bytes each leaves behind, with explicit tolerances where float math and driver rounding legitimately differ (see TODO.md for coverage and findings). It covers the output merger — the alpha test, blending, partial color masks and their combination over depth and stencil writes — and cache eviction, which it exercises by turning the budgets down. The texture work is covered the same way: every texture format, all sixteen wrap-mode pairs and the border color, nearest and bilinear filtering, level-of-detail selection and its bias and two-level blend, every combiner operation across stages with the buffer, constants and scales, multi-unit draws with the coordinate set and projection, texture-cache reuse, invalidation on rewritten bytes, and eviction, render-to-texture sampling, and fallback equivalence for lighting, fog, and procedural textures. It needs an OpenGL 4.3 context: on headless Linux it builds one through GLX on the software rasterizer (`xvfb-run -a cargo test -p zakuro-gpu --features opengl`), and where no context can be made the GL-dependent tests report why and pass while the conversion unit tests run everywhere.

## Implementation sequence

1. **Done.** Focused comparison tests for OpenGL coverage, interpolation, culling, scissoring, tiled-buffer conversion, depth/stencil state, depth mapping, lazy FBO caching and synchronization, and CPU-fallback equivalence run against the CPU path. Coverage and deferred cases are listed in TODO.md.
2. **Done.** Texture formats and sampling: the CPU decoder's texels upload into cached GL textures, and the shader reproduces the software rasterizer's wrap modes, filters and level-of-detail selection.
3. **Done.** The output merger (alpha test, blending, color masks) is accelerated and pinned by the differential suite, and the texture environment runs in the uniform-driven uber-shader — all six stages, every operation, the combiner buffer, constants and scales. The fallback keeps what GL cannot take (logic ops, a destination-side saturate factor) and what the shader does not run yet (fragment lighting, fog, procedural textures).
4. Move PICA vertex shader execution to OpenGL and handle geometry-shader draws through CPU preparation.
5. Add lighting, fog, procedural textures, and remaining framebuffer formats.
6. **Done as part of the MVP.** Keyed OpenGL color/depth targets already stay resident across draws, dirty GPU attachments are tracked, and synchronization resolves overlapping fallback draws, CPU reads/writes (the sync hooks), fills, and display transfers. The differential suite covers each of those paths; finer dirty-rectangle tracking to cut the writeback cost stays open in TODO.md.
7. Add resolution scaling, pipeline/resource caching, texture-pack support on the GPU path, and assess direct presentation and frame interpolation separately.
8. Validate the complete path on OpenGL 4.3 hardware across supported operating systems; retain software fallback for unsupported drivers and unimplemented states.
